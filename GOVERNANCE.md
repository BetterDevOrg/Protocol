## Decision-making

BetterDev uses a **maintainer consensus** model:

1. **Routine changes** (bug fixes, docs, small features) — any maintainer may merge after review.
2. **Significant changes** (protocol design, breaking API changes, contract upgrades) — discussed in a GitHub Issue or RFC-style PR; both maintainers should agree before merge.
3. **Community input** — contributors and users may open issues or PRs; maintainers review and respond in public.

We prefer transparent discussion on GitHub Issues and Pull Requests over private decision-making.

## Repository ownership

## Leadership changes

If a maintainer steps down:

1. They announce the transition in a public GitHub Issue.
2. Remaining maintainer(s) continue operations.
3. A new maintainer may be added by consensus of existing maintainers, documented in an Issue and reflected in this file.

## Fiscal sponsorship

BetterDev may seek fiscal hosting through [Open Source Collective](https://opencollective.com/open-source-collective) or similar. Financial decisions related to hosted funds follow the fiscal sponsor's policies; project technical direction remains with maintainers.
